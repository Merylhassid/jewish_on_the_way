## תמונת מצב לאחר הביצוע

- הושלם: endpoints ציבוריים ומוגנים לפי המטריצה, Optional JWT וצמצום שמות במניינים ובביקורות ציבוריות.
- הושלם: `SessionMode`, כניסה כאורח, פרופיל אורח, action guards ו־route guards.
- הושלם: מועדפים מקומיים לאורח, union עם מועדפי השרת לאחר התחברות ו־`returnTo` פנימי מאושר.
- הושלם: טיפול ב־401 אנונימי ללא forced logout והודעת `429` ידידותית במובייל.
- אומת: 235 בדיקות backend, 32 בדיקות חוזה HTTP, backend build, mobile TypeScript ו־ESLint ממוקד ללא שגיאות.
- הושלם: QA ידני, בדיקת deep links, בדיקת משתמש אורח/מחובר ובדיקת לוגים; ב־5,000 השורות האחרונות לא נמצאו `401`, ‏`Unauthorized` או Authorization ריק.
- הושלם: throttle ייעודי של 30 בקשות בדקה ל־`POST /search`; בקשה 31 הוחזרה כ־`429` בייצור. תקציב ה־LLM נשאר 50 ניסיונות ביום בתהליך היחיד.
- נותר לפני שחרור: להפעיל HTTPS ב־`api.jewishontheway.com` באמצעות reverse proxy ותעודה. כרגע Nest חשוף ישירות בפורט 3000 ולכן אין להפעיל `trust proxy`; לאחר התקנת ה־proxy יש לסמוך רק על מספר ה־hops/כתובות הידועות ולחזור על בדיקת ה־rate limit.

## עקרונות מחייבים

1. **תוכן ציבורי פתוח; זהות, כתיבה ותקשורת דורשות חשבון.**
2. **אכיפה בשתי שכבות:** גם בשערי route/screen וגם בנקודת הפעולה.
3. **הבקאנד הוא מקור הסמכות.** חסימת כפתור במובייל אינה תחליף ל־JWT על endpoint מוגן.
4. **אורח אינו משתמש מדומה.** לא נוצרים user, JWT או refresh token עבור מצב אורח.
5. **קהילה ציבורית משתמשת ב־DTO מצומצם.** אורח רואה תוכן, שם פרטי ואות בלבד; זהויות מלאות, נוכחות והשתתפות נשארות מוגנות.
6. **מועדפים מקומיים נשארים זמינים לאורח.** חשבון נדרש לסנכרון בין מכשירים, לא לשמירה מקומית.

## שלב 0 — חוזה התנהגות ובדיקות לפני שינוי guards

לפני פתיחת endpoint כלשהו:

1. להוסיף בדיקות HTTP/integration למטריצת `200 ללא token` מול `401 ללא token`.
2. להגדיר DTO ציבורי לכל תשובה שעלולה לכלול מידע של משתמש.
3. לוודא שמסכים ציבוריים אינם מבצעים בקשות מוגנות בזמן mount.
4. לתעד את מצב הבסיס של build, typecheck והטסטים.

בדיקות מינימום:

- endpoint ציבורי מחזיר `200` ללא `Authorization`.
- endpoint מוגן מחזיר `401` ללא token.
- token תקין ממשיך לקבל את כל השדות והיכולות הקיימים.
- token פג אינו הופך אוטומטית למצב אורח בלי הודעה.
- אין `Authorization: Bearer null` או `Bearer undefined`.

- שם היוצר יוצג לאורח כשם פרטי + האות הראשונה של שם המשפחה בלבד.
- למשתמש מחובר אפשר להחזיר את שם היוצר המלא דרך אותו Optional JWT.
- הצמצום יחול גם על רשימות (`GET /minyans`, `/nearby`) וגם על פרטי מניין (`GET /minyans/:id`).

### א'.4 הקשחת החיפוש החכם

`POST /search` ו־`GET /search/classify` כבר ציבוריים.

סטטוס ביצוע:

1. הושלם: `@Throttle` ייעודי של 30 בקשות לדקה ל־`POST /search`, לאחר מדידת שימוש מצטברת; אומת בייצור שבקשה 31 מחזירה `429`.
2. הושלם: מגבלת LLM נפרדת של 50 ניסיונות ביום בתהליך.
3. השרת רץ כרגע בתהליך PM2 יחיד. אם עוברים למספר תהליכים — נדרש מונה משותף ב־Redis/DB לפני ההרחבה.
4. כרגע אין reverse proxy והחיבור מגיע ישירות ל־Nest, לכן ה־IP הישיר תקין ואין להפעיל `trust proxy`. לאחר התקנת Nginx/Proxy יש להגדיר trusted hops מצומצם ולאמת מחדש.
5. הושלם: retention של `search_feedback` חל גם על חיפושי אורחים.
6. הושלם: המובייל מציג הודעת `429` ידידותית.

## שלב ב' — מודל session במובייל

### ב'.1 מצב יחיד במקום booleans סותרים

ב־`src/store/auth.tsx`:

```ts
type SessionMode = 'loading' | 'signedOut' | 'guest' | 'authenticated';
```

ה־context יספק לפחות:

```ts
sessionMode
isGuest
isAuthenticated
enterGuestMode()
login(...)
logout()
```

כללים:

- restore מתחיל ב־`loading`.
- token תקין → `authenticated`.
- אין token + `guest_mode=true` → `guest`.
- אין token ואין דגל → `signedOut`.
- התחברות מוצלחת מנקה `guest_mode`.
- התנתקות מנקה token, refresh token ודגל אורח → `signedOut`.
- forced logout בעקבות session שפג → `signedOut`, לא `guest`.

דגל אורח יכול להישמר ב־AsyncStorage; tokens נשארים ב־SecureStore במכשיר.

### ב'.2 כניסה כאורח

ב־`app/(auth)/login.tsx`:

- להוסיף כפתור משני ברור: “המשך כאורח”.
- `enterGuestMode()` ואז `router.replace('/(tabs)')`.
- משתמש authenticated שמגיע ל־login ממשיך להיות מנותב ל־tabs.
- להוסיף מחרוזות בעברית, אנגלית וצרפתית.

ב־`app/(tabs)/_layout.tsx`:

```tsx
if (sessionMode === 'loading') return <SplashState />;
if (sessionMode === 'signedOut') return <Redirect href="/(auth)/login" />;
```

גם אורח וגם משתמש מחובר רשאים להיכנס ל־tabs.

## שלב ג' — אכיפה בשתי שכבות

### ג'.1 action guard למסכים ציבוריים

ליצור מנגנון אחיד:

- `AuthPromptProvider` ברמת root.
- `useRequireAuth()` שמפעיל callback רק למשתמש מחובר.
- טקסט סיבה מותאם: ביקורת, דיווח, מניין וכו'.

דוגמה:

```tsx
const requireAuth = useRequireAuth();

onPress={() => requireAuth({
  reason: 'review',
  returnTo: pathname,
  action: () => setShowReviewForm(true),
})}
```

יש להפעיל את השער **לפני** פתיחת טופס ביקורת או דיווח, לא רק בזמן submit.

פעולות שדורשות action guard:

- פתיחת טופס ביקורת.
- פתיחת טופס דיווח.
- הצעת מקום חדש.
- יצירת מניין.
- הרשמה/ביטול הרשמה למניין.
- כניסה לצ'אט מתוך פרטי מניין.

מועדפים אינם עוברים ב־action guard עבור שמירה מקומית.

### ג'.2 route guard למסכים פרטיים

כל מסך פרטי צריך לבדוק auth בכניסה, גם אם בדרך כלל מגיעים אליו מכפתור מוגן.

מסכים מוגנים ב־1.0:

- `minyan/chat/[id]`
- `minyans/my-minyans`
- כל `hosting/*`
- `blocked-users`
- `admin`

ה־guard צריך לכסות גם deep link, התראה ו־navigation ישיר. לא להציג מסך פרטי מאחור ואז לפתוח modal מעליו.

`saved.tsx` נשאר פתוח לאורח משום שהוא מציג מועדפים מקומיים.

כניסת האירוח במסך היעד נשארת גלויה לצורכי גילוי והמרה. לחיצה של אורח תציג טיזר קצר עם הרשמה/התחברות, אך לא תנווט למסך האירוח ולא תטען `/hosting/*`. אותו route guard ממשיך לחסום כניסה ישירה דרך deep link או התראה.

### ג'.3 פרופיל אורח

בטאב הפרופיל:

- לא לבצע את בקשות `/minyans/mine` ו־`/hosting/*/mine` עבור אורח.
- להציג מסך אורח ייעודי.
- להסביר בקצרה את ערך החשבון: סנכרון מועדפים, קהילה, מניינים ואירוח.
- להציע “הרשמה” ו“יש לי חשבון”.

## שלב ד' — מועדפים מקומיים וסנכרון

### ד'.1 אורח

- `FavoriteButton` קורא וכותב רק ל־AsyncStorage.
- אין ניסיון שקט לקרוא או לכתוב ל־`/favorites` כאשר `sessionMode === 'guest'`.

### ד'.2 משתמש מחובר

- ממשיך להסתנכרן עם `/favorites`.
- לאחר התחברות, אם קיימים מועדפים מקומיים, לבצע union אל השרת.
- אין למחוק מועדף שרת בגלל שהמפתח אינו קיים מקומית.
- לאחר merge מוצלח אפשר להשאיר cache מקומי לצורך offline.

אם merge אינו נכנס לגרסה הראשונה, לא למחוק את המועדפים המקומיים; להציג סנכרון רק מההתחברות הבאה שבה המנגנון מוכן.

היעד צריך לשרוד:

- login
- register
- verify-email
- onboarding

כללים לגרסה הראשונה:

- לאחר הצלחה חוזרים למסך המקורי.
- הפעולה המקורית אינה מתבצעת אוטומטית; המשתמש לוחץ שוב.
- לא לקבל URL חיצוני או route שאינו ברשימת הנתיבים הפנימיים.
- אם `returnTo` חסר או אינו תקין — לחזור ל־`/(tabs)`.

## שלב ו' — interceptor ושגיאות 401

ב־`src/api/client.ts`:

- בקשה אנונימית ללא Authorization שקיבלה `401` → לדחות את השגיאה בלי forced logout.
- בקשה שנשלחה עם access token → לנסות refresh פעם אחת.
- refresh נכשל → לנקות session ולעבור ל־`signedOut`.
- לא להכניס בקשות auth ללולאת refresh.
- מסך ציבורי לא ינווט ל־login רק בגלל endpoint מוגן שנקרא בטעות; הבקשה עצמה עדיין תיכשל ותירשם לצורך אבחון.

## שלב ח' — QA ושערי שחרור

> הושלם ידנית ב־20.07.2026 על ידי בעל המוצר; לא דווחו כשלים פתוחים. בדיקת הלוגים לאחר מכן הייתה נקייה מ־401 חריגים ומ־Authorization ריק.

### בדיקות אוטומטיות

- מטריצת auth לכל endpoint ששונה.
- Optional JWT במניין יחיד: אורח, token תקין, token פגום.
- merge מועדפים מקומיים לחשבון.
- interceptor: anonymous 401, refresh success, refresh failure, concurrent 401.
- route guards לנתיבים פרטיים.

### מסלול ידני כאורח

1. פתיחה נקייה → login → “המשך כאורח”.
2. יעדים, מסעדות, בתי כנסת, מפה ומצפן עובדים.
3. חיפוש חכם עובד ומציג `429` בצורה תקינה בעת הגבלה.
4. קריאת ביקורות עובדת; לחיצה על כתיבה פותחת מודאל לפני הטופס.
5. מועדף נשמר ומופיע ב־saved לאחר restart.
6. רשימת מניינים ופרטים עובדים; שמות משתתפים אינם נחשפים.
7. יצירה/הרשמה/צ'אט מניין פותחים שער התחברות.
8. community נפתח לקריאה גם ב־deep link; פעולות השתתפות, hosting, blocked-users ו־admin נשארים חסומים.
9. פרופיל אורח אינו שולח בקשות “שלי”.
10. הרשמה/התחברות מהמודאל מחזירה למסך המקורי.

### מסלול ידני למחובר

1. כל היכולות הקיימות ממשיכות לעבוד.
2. מועדפים מקומיים מתמזגים בלי למחוק מועדפי שרת.
3. `isRegistered` במניין נכון.
4. משתתפים, קהילה, אירוח ופרופיל זמינים לפי הרשאות.
5. token פג עובר למסך login עם הודעה מתאימה.

### שערי שחרור

- backend: build + כל הטסטים.
- mobile: `npx tsc --noEmit`.
- mobile: ESLint ממוקד לקבצים ששונו.
- בדיקה על מכשיר iOS אמיתי ו־Android.
- בדיקת deep links והתראות כאשר המשתמש אורח או signed out.
- בדיקת לוגים שאין Authorization ריק ושאין הצפת 401.

## סדר ביצוע

1. שלב 0 — בדיקות חוזה ומצב בסיס.
2. שלב א' — endpoints ציבוריים, Optional JWT וחיפוש.
3. שלב ב' — session state וכפתור אורח.
4. שלב ג' — action guards, route guards ופרופיל אורח.
5. שלב ד' — מועדפים מקומיים ו־merge.
6. שלבים ה'–ו' — returnTo ו־interceptor.
7. שלב ז' — פרטיות ו־App Review.
8. שלב ח' — QA מלא ופריסה מדורגת.

אין לפרוס את שינויי הבקאנד לפני שהמובייל המתאים מוכן ונבדק, ואין לבנות גרסת חנויות לפני השלמת מסלולי האורח והמשתמש המחובר.
