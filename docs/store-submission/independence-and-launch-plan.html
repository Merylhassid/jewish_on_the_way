שינוי אסטרטגי מהתוכנית הקודמת: התוכנית הקיימת הניחה הגשה דרך המכללה (חשבון Google Play, Apple Team של המכללה — סעיף 0.2 שם). מסמך זה מניח מעבר לעצמאות מלאה: שרת שלך, חשבון Apple שלך, חשבון Google שלך. זה מבטל את החסם של סעיף 0.2. כל שאר ההכנות הטכניות (EAS, app.json, metadata, מדיניות פרטיות, מחיקת חשבון) נשארות תקפות במלואן.

איציאה משרת המכללה לשרת עצמאי

א.1 למה בכלל לעבור

  • שרת המכללה אינו שלך — יכול להיסגר/להיחסם בכל רגע בלי התראה
  • למשתמש student אין הרשאות sudo — כל שינוי תשתית תלוי במארק במכללה (זו הסיבה שסעיף 0.1 בתוכנית הקיימת תקוע)
  • אפליקציה עם משתמשים אמיתיים לא צריכה להיות מבוססת על תשתית שאינה בשליטתך

המלצה: Hetzner CX22.

א.3 שלבי המעבר

  • פתיחת חשבון Hetzner + הקמת שרת Ubuntu 22.04 LTS
  • הקשחה: משתמש לא-root עם sudo, SSH key בלבד, ufw firewall
  • התקנת Node.js, PM2, Nginx, Certbot
  • העברת קוד, npm ci && npm run build, .env מוזן ידנית בשרת (לא מ-Git)
  • pm2 start dist/main.js --name jewish-on-the-way-api, pm2 save, pm2 startup
  • Nginx reverse proxy מ-443 לפורט הפנימי (3001)
  • עדכון DNS: api.jewishontheway.com → IP של השרת החדש
  • certbot --nginx -d api.jewishontheway.com — עכשיו אתה מריץ בעצמך, לא ממתינים למכללה
  • בדיקת socket.io על wss:// (צ'אט, מניינים, אירוח)
  • לשמור את שרת המכללה כ-fallback שבוע-שבועיים לפני כיבוי
  • גיבוי אוטומטי יומי (Hetzner, ~$1-2/חודש נוסף) — מומלץ מאוד

בבדיקת מסד הנתונים (Neon)

ב.1 מה תקין

  • DB בענן (Neon), לא מותקן על שרת המכללה — אין תלות
  • חיבור עם SSL (DB_SSL=true)
  • הקוד קורא פרטי חיבור ממשתני סביבה (.env.example) — תבנית נכונה

ב.2 🚨 הבעיה הקריטית — סיסמה חשופה

מחרוזת החיבור המלאה ל-Neon, כולל סיסמה, מופיעה כרגע בטקסט גלוי ב-CLAUDE.md בשורש הפרויקט (ב-Git!), וגם ב-29 קבצי סקריפט עזר תחת backend/. זה סעיף 0.13 בתוכנית הקיימת — אבל הסיסמה חשופה בפועל, עכשיו, לא רק תיאורטית.

חובה לפני שהאפליקציה יוצאת החוצה:

  • להחליף את סיסמת המשתמש ב-Neon (Console → Roles → Reset password)
  • להסיר את מחרוזת החיבור מ-CLAUDE.md ומכל סקריפט עזר → משתנה סביבה בלבד
  • לבדוק אם הסיסמה הישנה בהיסטוריית Git → לשקול ניקוי היסטוריה אם המאגר משותף עם המכללה
  • לעדכן פרטי חיבור בכל סביבה פעילה אחרי ההחלפה

לא לבצע בלי אישור מפורש — משבית זמנית גישה לכל מי שמחזיק את הסיסמה הישנה.

ד.2 ⚠️ דרישת Closed Testing לחשבונות חדשים

מדיניות Google הנוכחית (לאמת מול Play Console — משתנה) מחייבת חשבונות מפתח אישיים חדשים להריץ closed testing עם ~12-20 בודקים במשך 14 יום רצופים לפני קבלת גישה לפרסום ל-production. אי אפשר "לפרסם ומוכן" מיד — יש לתכנן שבועיים מראש, ולהתחיל מוקדם ככל האפשר במקביל להכנת iOS.

ד.3 מה שנשאר למלא ב-Play Console

  • Data Safety form (כולל Cloudinary לתמונות, Anthropic ל-smart search)
  • Content rating questionnaire (IARC) — כנראה "Everyone"/"3+"
  • Target audience & content declarations
  • Ads declaration — "No ads"
  • App access — פרטי חשבון בדיקה
  • Government apps / COVID tracing / Financial / Health — "לא" לכולם

מה נשאר תקף מהתוכנית הישנה

כל שאר הפרטים הטכניים — Metadata מאושר, EAS+app.json, מדיניות פרטיות בטיוטה, מחיקת חשבון, שמירת לוגים — מפורטים ב-store-submission-plan.html ולא תלויים בשאלת "מי מגיש". הדבר היחיד שהתבטל: תיאום מול המכללה (סעיף 0.2) — הוחלף בפתיחת חשבונות Apple/Google עצמאיים (חלקים ג'+ד' כאן).

מסמך משווה

קודקס הכין גרסה מקבילה למסמך הזה — codex-independence-and-launch-plan.html / .md. היא בדקה בפועל את ה-DB (PostgreSQL 17.10, PostGIS, ~37MiB), כללה מקורות רשמיים מצוטטים לכל מספר, וזיהתה שני חסמים אמיתיים שהמסמך הזה לא כיסה: (1) דרישת Apple Guideline 1.2 לסינון תוכן משתמשים — אומת בקוד שאין מנגנון כזה כרגע, ו-(2) הצהרת DSA Trader/Non-Trader הנדרשת מ-Apple להפצה באיחוד האירופי. מומלץ לעבוד לפי הגרסה של קודקס; המסמך הזה נשמר להשוואה ולהיסטוריה.
